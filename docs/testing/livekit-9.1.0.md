# نتیجهٔ آزمون جلسه‌ها — نسخهٔ 9.1.0

تاریخ: ۱۴۰۵/۰۹/۰۴. محیط: PHP 8.4.27، MariaDB 11.8.9، Laravel 12 و Chromium/Playwright روی Linux. هیچ تستی به دیتابیس تولید یا حساب LiveKit Cloud کاربر متصل نشده است.

## آزمون‌های موفق

- `php bin/test-meetings.php`: SQL و رمزگذاری واقعی داخل تراکنش rollback؛ شبکهٔ Cloud شبیه‌سازی شده است. ساخت صوتی/تصویری، یک جلسهٔ باز برای پروژه، جلوگیری از ورود و دعوت بیگانه، تفاوت نقش بین پروژه‌ها، دعوت/رد/پذیرش، شنونده و ارتقا، محدودسازی منابع، رضایت یک‌بارمصرف و ابطال رضایت قدیمی پس از محدودیت جدید، حذف عضویت، اخراج/دعوت دوباره با هویت تازه، توکن محدود و بدون مجوز مدیریت، ماندگاری و رمزگذاری چت، جلوگیری از پیام تکراری، ۲۰۵ پیام و صفحه‌بندی before/after، مرز ۴۰۰۰ نویسهٔ فارسی، رد نشانگر جلسهٔ دیگر، پایان در خطای شبکه و بازیابی پاک‌سازی، امضای webhook و بدنهٔ دستکاری‌شده، رویداد تکراری و رویداد قدیمی‌تر بررسی شدند.
- `KARLIX_MEETING_UI_ONLY=1 ... node bin/test-meetings-browser.js`: دو نشست واقعی مرورگر و دیتابیس واقعی؛ رسانه در این حالت با stub صریح آزمون جایگزین شد. پیش‌نمایش دستگاه‌ها با دستگاه مصنوعی Chromium، ورود از کارت پروژه، ارتقای عضو، کنترل شخصی میکروفن، رضایت صریح، چت و escape کردن نمونهٔ XSS، نمایش تاریخچه پس از پایان، خاتمه برای همه، رابط صوتی مستقل، خروج داوطلبانه، موبایل ۳۹۰ پیکسلی بدون اسکرول افقی و تغییر تم روشن/تاریک پاس شدند. خطای JavaScript مشاهده نشد. پیام‌ها از API واقعی و دیتابیس خوانده شدند؛ فلوهای Cloud از driver صرفاً CLI در محیط تست عبور کردند.
- HTTP واقعی: دسترسی بیگانه 404؛ نوشتن بدون CSRF برابر 419؛ API بدون احراز هویت 401؛ Bearer فقط‌خواندن برای دریافت وضعیت 200 و برای صدور توکن رسانه 403؛ webhook بدون امضای معتبر 401. در نصب بدون تنظیم Cloud، ساخت جلسه HTTP 503 با پیام روشن MEETING_NOT_CONFIGURED برگرداند؛ متن عمومی خطای داخلی جای راهنمای تنظیمات را نگرفت. هدرهای واقعی صفحهٔ جلسه برای دوربین/میکروفن self و CSP مخصوص Cloud بررسی شدند. در تست محلی فقط CSP سند آزمون اجازهٔ اتصال localhost گرفت؛ هدر تولید تغییر داده نشد.
- migration 059 دو بار روی نسخهٔ 9.0.1 در دیتابیس موقت مستقل اجرا شد: چهار جدول افزوده شدند؛ ساختار هر ۴۴ جدول قبلی با SHOW CREATE TABLE مقایسه شد و دادهٔ پروژهٔ نمونه دقیقاً ثابت ماند. دیتابیس موقت در پایان حذف شد.
- `bin/test-laravel-contracts.js`: هر ۷۴ مقایسهٔ قرارداد قبلی با مسیر legacy و Laravel، از جمله APIها و HTML تحلیل ادمین پاس شدند. فقط زمان پویای clock.now در مقایسهٔ HTML ادمین عادی‌سازی شد؛ منطق ادمین عوض نشده است.
- `bin/test-laravel-runtime.php`: قراردادهای ۲۳۰ مسیر قبلی و بومی‌بودن تمام ۲۶۴ handler فعلی، نشست، Eloquent/رمزگشایی، Policy، Guard، تراکنش مشترک و محرمانگی پیوست‌ها پاس شدند.
- `bin/check-dependencies.php`: هر ۷۴ وابستگی تولید و ۴۰۶۰ کلاس نگاشت‌شده همچنان کامل‌اند. Composer جدید یا وابستگی PHP جدیدی به هاست تحمیل نشده است؛ SDK رسمی مرورگر همراه پروژه است.
- آزمون‌های قبلی تفکیک دسترسی پروژه، تکرار تسک (روزانه، هفتگی، ماهانه و هر X روز)، سهمیهٔ فضای ذخیره‌سازی و golden workload در PHP و JavaScript پاس شدند.
- syntax فایل‌های تغییرکردهٔ PHP/JavaScript و ساخت آیکون‌ها بررسی شد. PDF دیتابیس دوباره ساخته شد: ۴۸ جدول و ۴۸۱ ستون. متن خروجی و صفحات جلسه‌ها بررسی شدند.

## آزمون واقعی رسانه که موفق نشد / باقی مانده است

سرور موقت رسمی LiveKit **1.13.11** روی localhost راه افتاد. API واقعی CreateRoom/ListRooms/ListParticipants/RemoveParticipant/DeleteRoom از adapter آزمون فراخوانی شد؛ JWT نیز برای سرویس پذیرفته شد و signaling با SDK رسمی مرورگر تا مرحلهٔ برقراری PeerConnection پیش رفت.

اجرای مرورگر با SDK واقعی، به خطای `could not establish pc connection` رسید. Chromium مدیریت‌شدهٔ محیط سیاست `WebRtcIPHandling=disable_non_proxied_udp` دارد و WebRTC محلی در این محیط برقرار نشد. این محدودیت تغییر داده نشد. نتیجهٔ حالت UI-only، تأیید انتقال واقعی صدا/تصویر یا کیفیت تماس نیست.

کاربر هنوز حساب/پروژهٔ LiveKit Cloud نساخته است. بنابراین اتصال چند کاربر به Cloud، دریافت واقعی صدای یکدیگر، تصویر دوربین، اشتراک صفحه، قطع اینترنت واقعی و اتصال مجدد رسانه، اخراج و ابطال JWT در خود Cloud، کیفیت اپراتورهای ایران، مرورگرهای واقعی موبایل و ظرفیت/هزینهٔ حساب **تأیید نشده‌اند**. رویداد reconnect فقط در آزمون رابط شبیه‌سازی شد. این موارد پس از تنظیم حساب با راهنمای `docs/LIVEKIT.md` باید روی سرویس واقعی آزموده شوند؛ قابلیت از نظر تماس واقعی هنوز پذیرش نهایی نشده است.

## محدودیت‌های دامنه

- ضبط جلسه و E2EE رسانه اضافه نشده‌اند؛ رمزگذاری چت دیتابیس از کلید فعلی استفاده می‌کند.
- مجوز پروژهٔ تازه‌ای تعریف نشده است؛ ساخت با edit_project همان پروژه و مدیریت با میزبان است. برای جدول مجوز مستقل جلسه، باید بعداً قرارداد نقش‌ها جداگانه طراحی شود.
- کران دقیقه‌ای توصیه می‌شود تا تغییرات ادمین و پاک‌سازی معطل شبکه حتی بدون مرورگر جبران شوند؛ webhook امضاشده هم باید در Cloud تنظیم شود.
- سازگاری SQL با ساختار MySQL 5.7+/MariaDB 10.3+ حفظ شده، اما اجرای این نسخهٔ جدید روی همهٔ نسخه‌های PHP/MySQL یا خود هاست اشتراکی کاربر انجام نشده است.
- Graphify برای این workspace هیچ مخزن مجازی برنگرداند؛ بررسی از سورس محلی انجام شد. Elis Token Saver فقط یک برآورد رایگان برگرداند؛ سهمیهٔ رایگان اجرای طرح صفر بود و مرحلهٔ خرید/رزرو طرح فراخوانی نشد. هیچ صرفه‌جویی اندازه‌گیری‌شده‌ای ادعا نمی‌شود.
