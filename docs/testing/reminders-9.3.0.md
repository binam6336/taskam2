# یادآوری تکرارشونده تسک عقب‌افتاده ۹.۳.۰

تاریخ: ۱۴۰۵/۰۹/۰۷. محیط محلی PHP 8.4.27، MariaDB 11.8.9 و Chromium با دیتابیس `_test`. هاست و دستگاه واقعی استفاده نشدند.

## پیاده‌سازی

- زیر تاریخ انجام، عدد اختیاری ۱ تا ۱۰۰۰ و انتخاب دقیقه/ساعت/روز/هفته/ماه در ثبت، ویرایش و ویرایش سریع سررسید قرار دارد. بدون تاریخ، کنترل مخفی و مقدار پاک می‌شود. خالی = بدون تکرار. ویرایش نیازمند `edit_due` همان تسک است.
- فیلدهای nullable به نام `reminder_every` و `reminder_unit` با migration افزایشی `060` و ثبت مستقل هر ستون در Schema اضافه شدند. داده قدیمی بازنشانی نمی‌شود. این دو پارامتر عملیاتی برای زمان‌بندی، خارج از رمزگذاری متن هستند؛ کلید رمزگذاری تغییر نکرده است.
- زمان اول برای تاریخ دارای ساعت، همان ساعت و برای تاریخ بدون ساعت، ابتدای روز بعد است. پنجره قدیمی ۱۲۰ دقیقه حذف شد تا اعلان اولیه پس از قطعی از دست نرود. برای تکرار، `DATE_ADD` از `notified_at` استفاده می‌شود؛ ماه میلادی و پایان ماه کوتاه‌تر تعدیل می‌شود. پس از قطعی، فقط یک نوبت ارسال و فاصله بعدی از همان زمان شروع می‌شود.
- `ReminderSchedule` منبع شرط مشترک خواندن/گرفتن نوبت در مرورگر و Web Push است. تکمیل، بررسی، آرشیو، مسدودی تسک/پروژه و از دست‌رفتن عضویت مسئول، ارسال را متوقف می‌کنند.
- مرورگر ابتدا `ids` و نقشه JSON از `reminder_ref` را به POST فعلی `/notifications/ack` می‌فرستد؛ پاسخ افزایشی `claimed` فقط شناسه‌های عمومی برنده را دارد. `UPDATE` آخرین اعلان و تنظیمات را با مقدار خوانده‌شده و شرط آماده‌بودن مقایسه می‌کند. سپس فقط نوبت‌های گرفته‌شده نمایش داده می‌شوند. حافظه دائمی `tk_due_<id>` دیگر مانع نوبت بعد نیست. کلاینت قدیمیِ بدون ref از مسیر قبلی تأیید قابل استفاده است؛ تا بارگیری JS جدید، منطق قدیمی مرورگر خودش تکرار را نمایش نمی‌دهد.
- `sweepDue` پیش از صف‌کردن، همان claim را انجام می‌دهد؛ اجرای هم‌زمان دیگر همان نوبت را صف نمی‌کند. حداکثر ۲۰۰ مورد در sweep و ۵۰ مورد در خواندن/تأیید مرورگر. صف‌کردن معادل تضمین تحویل شبکه نیست؛ در صورت خطای شبکه، چرخه بعدیِ فعال دوباره تلاش می‌کند.
- API و جزئیات تسک تنظیمات را برمی‌گردانند؛ ویرایش در تاریخچه ثبت می‌شود. نوبت بعدِ تسک تکرارشونده تنظیم فاصله را کپی می‌کند و `notified_at` مستقل دارد. legacy و Laravel هر دو به‌روز شدند؛ مسیر/متد API قبلی حفظ شد.

## آزمون‌های اجراشده

- `bin/test-task-reminders.php`: هر ۳۶ بررسی موفق؛ ثبت و ذخیره، جلوگیری از claim حساب بیگانه، یک برنده برای دو کانال، رد تأیید قدیمی، نوبت بعد، همه پنج واحد، روز بدون ساعت و نبود تأخیر در همان روز، توقف در چهار وضعیت، خاموش‌کردن بدون اعلان تازه، مجوز `edit_due`، شش ورودی نامعتبر، ارقام فارسی، پاک‌شدن با حذف تاریخ، پروژه مسدود، مرز پایان فوریه، صف واقعی `Push::sweepDue`، اجرای دوباره بدون تکرار، نوبت بعدی کران، ارث‌بری تنظیمات در نوبت مستقل و ثبت تاریخچه. تست‌ها transaction rollback شدند؛ صف خصوصی تست قبل از shutdown پاک شد و انتقال Push به شبکه اجرا نشد.

## اجرا روی هاست

برای مرورگر بسته، Cron هر دقیقه `php /absolute/path/to/bin/push-cron.php` یا فرمان Laravel متناظر را با PHP 8.2+ همان هاست اجرا کند؛ راهنما در `docs/DEPLOY.md`. سایت با بازدید نیز دقیقه‌ای یک sweep دارد؛ بدون cron یا بازدید، اجرا پیش نمی‌رود. HTTPS، تنظیمات Push موجود، اشتراک و اجازه دستگاه برای دریافت واقعی لازم است. نصب cron و دریافت روی دستگاه کاربر در این محیط تست نشده است.
